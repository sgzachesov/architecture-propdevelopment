# Проверочный лист

## I. Управление доступом

| № | Вопрос | Да/нет | Комментарий |
|---|---|---|---|
| 1 | Используется ли многофакторная аутентификация (MFA) для доступа к критическим системам и сервисам? | н/д | Аутентификация внешних пользователей идёт через Keycloak, сотрудников — через Active Directory, однако применение MFA в описании не отражено — требуется проверка. |
| 2 | Настроены ли требования к сложности паролей и их регулярное обновление? | н/д | Политики паролей не описаны; техническая возможность есть в Keycloak и AD, но подтверждение отсутствует. |
| 3 | Проводится ли аудит и пересмотр учётных записей с повышенными привилегиями на регулярной основе? | н/д | Аудит привилегированных учётных записей в описании не упоминается. Риск-факторы из кейса: один специалист по ИБ и нарушенная передача информации между командами; требует проверки. |
| 4 | Реализован ли принцип минимальных привилегий при назначении ролей и прав доступа? | Нет | Подтверждена обратная ситуация: партнёр одной УК может видеть и изменять данные другой УК, клиенты видят чужие данные — разграничение доступа не работает на уровне объектов. |
| 5 | Автоматически ли удаляются или деактивируются учётные записи после увольнения или изменения должности сотрудников? | н/д | Процесс не описан. |
| 6 | Ведётся ли журналирование всех операций доступа к системам и данным? Кто имеет доступ к журналам? | н/д | В описании системы данные о журналировании операций доступа, единой системе мониторинга и регламенте доступа к журналам отсутствуют — требуется проверка в ходе аудита. |
| 7 | Используются ли механизмы контроля доступа на основе атрибутов для повышения гибкости управления доступом? | н/д | ABAC в описании не упоминается. Из кейса известно, что текущее разграничение не изолирует данных УК друг от друга; требует проверки. |
| 8 | Используются ли системы аутентификации пользователей для доступа к системам? | Да | Keycloak (auth-service-1) для покупателей и собственников, Active Directory для сотрудников (менеджеры, бухгалтер, бизнес-аналитик). |
| 9 | Созданы ли замкнутые контуры для подсистем, работающих с чувствительными данными? | Нет | Сырые данные передаются из БД приложений в хранилище (CDC, по C4-диаграмме), а «со стороны систем обработки данных нет ограничений на доступ к данным» (из описания проблемы «Нарушен контроль данных») — изоляции чувствительных данных не подтверждена. |
| 10 | Ограничен ли доступ к системам из внешних источников? | Частично | Доступ клиентов и собственников — через firewall; партнёрский контур (API УК) подключён без единых политик безопасности. |
| 11 | Ведётся ли единый реестр учётных записей? | Нет | Реестр разрознен: две службы Active Directory (финансы и бизнес/данные) плюс Keycloak для внешних пользователей. |
| 12 | Используются ли средства управления учётными записями на базе единого реестра? | Частично | AD является базой для учётных записей сотрудников, но реестр не единый и не покрывает клиентские учётные записи (Keycloak). |
| 13 | Применяются ли средства для отзыва прав доступа? | н/д | Средства отзыва прав в описании не упоминаются. Своевременность отзыва зависит от процессов ИБ, которые в кейсе нарушены (один специалист по ИБ, разорванная передача информации); требует проверки. |
| 14 | Используются ли средства централизованного контроля доступа? | Нет | Единой IAM/IDM-системы не выявлено; контроль рассредоточен между Keycloak и двумя службами каталогов. |
